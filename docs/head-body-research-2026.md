# Full-head and face/body research through October 6, 2026

The current AlphaFace backend replaces facial identity; enlarging its mask cannot turn it into head/body synthesis. Full-head replacement must generate hair, ears, skull silhouette and any newly exposed background. Face-plus-body replacement adds clothing/shape, articulated limbs, contact objects and scene lighting. These need a separate generative or avatar backend.

| Method / date | What it does | Verified availability and practical decision |
|---|---|---|
| [GHOST 2.0](https://arxiv.org/abs/2502.18417), February 2025 / June revision | One-shot head reenactment, hair/ears/silhouette transfer, skin-color blending and background inpainting | [Official code](https://github.com/ai-forever/ghost-2.0), Apache-2.0, and actual checkpoints are released. A separate local inference adapter now produces head images using strictly matched inference tensors; training-only DECA/FLAME and gaze-loss dependencies are omitted. Five real/screenshot diagnostic renders completed on CPU; four raw frames took 30.3 seconds including loading. Visible chin/neck boundaries, coarse face texture and hand occlusion errors remain. Not enabled as a live-camera mode. |
| [DirectSwap](https://arxiv.org/abs/2512.09417v3), September 11, 2026 revision | Whole-head video swapping with paired cross-identity supervision and background restoration | [Official repository](https://github.com/Yanan-Wang-cs/DirectSwap) is Apache-2.0 but currently contains documentation/demos; code, weights and data remain scheduled. Strong task match for an offline head mode; no local inference possible with verified released assets. |
| [AHS](https://arxiv.org/abs/2604.15857), April 17, 2026 / CVPR | Head synthesis in upper-body images, hair/accessories and expression/pose | [Project](https://keh0t0.github.io/AHS/) says code coming soon. Primarily image head synthesis, not demonstrated live-camera video integration. No verified distributable implementation/weights or local benchmark. |
| [GSwap](https://arxiv.org/abs/2603.23168), March 24, 2026 / TVCG | Few-shot head-domain adaptation plus dynamic Gaussian portrait field on SMPL-X, with background re-rendering | [Project](https://ustc3dv.github.io/GSwap/) says code coming soon. Relevant to head/neck continuity; subject adaptation and body-model licensing require an independent pipeline. No local training or inference. |
| [Wan-Animate-2](https://arxiv.org/abs/2608.06009), August 2026 | End-to-end character animation from reference image and driving video; pose/expression/viewpoint conditioning; distilled variants | [Official code](https://github.com/Wan-Video/Wan-Animate-2) and [14B weights](https://huggingface.co/Wan-AI/Wan2.2-Animate-2-14B) released August 7 under Apache-2.0. Strong released recent candidate for full-body animation, but not automatically equivalent to exact scene-preserving replacement. Official defaults target eight A800s; 480p tested on two A800s. Separate Torch 2.7/CUDA 12.6/FlashAttention setup. No 4090 benchmark or silent download. |
| [Wan-Animate](https://arxiv.org/abs/2509.14055), September 2025 | Unified animation **and explicit character replacement**, with pose/face/background/mask inputs and relighting | [Official implementation](https://github.com/Wan-Video/Wan2.2) provides replacement preprocessing/inference and released Animate-14B assets. More concrete starting point for scene-preserving offline face/body replacement. The repository's 24 GB example applies to **TI2V-5B**, not proof that Animate-14B fits a 4090. Evaluate quantization/offload separately before promising local speed. |
| [LiveAnimate](https://arxiv.org/abs/2608.11745), August 2026 | Causal full-body animation from reference image plus streaming body/facial controls | [Project](https://liveanimate.github.io/) reports 19.63 FPS on **two H100s**, using a 14B model; [repository](https://github.com/liveanimate/LiveAnimate) says code coming soon. | [ReGenHuman](https://arxiv.org/abs/2606.14972), June 12, 2026 | Full-body video anonymization using pose, segmentation and depth conditioning | Regenerates appearance from identity-free structure rather than transferring a chosen identity. No local runtime or verified asset license established here. |

Most recent-paper entries remain research review; GHOST 2.0 and the Wan-Animate local experiment are exceptions. GHOST inference weights and auxiliary models were downloaded separately and hashed. No weights or private diagnostic images are distributed. Published throughput is on the authors' hardware. A 14B BF16 parameter set alone is approximately 28 GB before activations and auxiliary models (arithmetic estimate), exceeding this 24 GB GPU; efficient variants, quantization or offload require measured validation.

The isolated GHOST adapter is `python -m deepfake.experimental.ghost_head --source reference.jpg --target frame.png --output results`, using a reviewed runtime directory selected with `DEEPFAKE_GHOST_RUNTIME`. That directory must contain `ghost-2.0/` at commit `b485e1a7f87a7190528e4ade8f0fef86317af7c4`, `stylematte_models.py` from the author, and the separately downloaded `weights/` (aligner, blender, head parser, StyleMatte and LaMa). Use a dedicated Python 3.12 environment with Torch 2.6/torchvision 0.21, transformers 4.48.2, SciPy, NumPy 2.2.6, einops, PyYAML, ONNX Runtime and simple-lama-inpainting 0.1.2. This image experiment applies visible disclosure; it is separate from the signed production video-export pipeline.

For body replacement, the original [Wan-Animate paper](https://arxiv.org/abs/2509.14055) and [official implementation](https://github.com/Wan-Video/Wan2.2) are a better established scene-replacement starting point than assuming the newer animation-only model is equivalent. The [ComfyUI native replacement workflow](https://docs.comfy.org/tutorials/video/wan/wan2-2-animate) supplies the same reference / face / body-pose / masked-background / character-mask controls. Its `Mix` mode replaces a character; `Move` animates a reference scene. The masked background must black out the expanded person region; feeding the original unmasked person there leaks the target clothing/identity into the result.

Verified local model sizes: QuantStack Animate-14B Q4_K_M is 11,496,331,072 bytes; the FP8 text encoder is 6,735,906,897 bytes; CLIP vision 1,264,219,396 bytes; VAE 253,815,318 bytes. Total 19.75 GB, plus roughly 536 MB for DWPose/SAM2 preprocessing. These are separately cached; a FP8 generator is still approximately 17–18 GB on disk and is not automatically a 14 GB all-in runtime. A private 512×288, nine-frame, 20-step graph runs on a 4090 through ComfyUI 0.3.60 and ComfyUI-GGUF; segmentation and facial/body controls are genuine model outputs. Five graph runs completed: initial unmasked conditioning retained target clothing; corrected masking and full-reference letterboxing transferred the suit/tie but produced severe facial/color artifacts. Adding the official relighting adapter and guidance of 1 did not resolve them; a same-controls BF16 run produced essentially the same defects. The nine-frame FP16 relighting graph took 82 seconds; BF16 took 117 seconds including fresh loading on the shared GPU. This configuration fails facial-quality review and is retained only as an offline research prototype. It does not establish reliable identity transfer, longer temporal consistency, exact occlusion preservation or full-body coverage. A head-and-shoulders reference cannot constrain unseen torso/leg appearance.

Practical route: implement a separately isolated **offline replacement** adapter around the released Wan-Animate replacement workflow; evaluate Wan-Animate-2 for animation in a second experiment. Keep live facial swapping independent. Tests must cover hair silhouettes, ear/neck boundaries, hand/object occlusion, background restoration, source identity, body shape/clothing, temporal consistency and audio alignment. Preserve signed disclosure on exported output. No dummy head/body preset or expanded facial mask is exposed as a working capability.

### Reproducing the isolated Wan replacement controls

The experiment uses ComfyUI tag `v0.3.60` (`b8730510db30c8858e1e5d8e126ef19eac395560`) and ComfyUI-GGUF `6ea2651e7df66d7585f6ffee804b20e92fb38b8a`. Keep their environment separate from the live application. Start the local server with `--lowvram --cpu-vae --preview-method none`. Register the separately cached generator, text encoder, CLIP vision and VAE through ComfyUI model paths; put `wan2.2_animate_14B_relight_lora_bf16.safetensors` in `models/loras`. The additional relighting adapter is 1,436,673,432 bytes, SHA-256 `5f4b6b9d3bc745a86e7bfd511f3880d90cf59c3bded9584d92c028f583fa74a3`, from Comfy-Org's Wan 2.2 repackaging at revision `ee6f4a40737a995bf5818954cfce6d59443b0f04`. Replacement uses the authors' base-model settings: 20 steps, guidance 1, shift 5; it does not use the separate six-step acceleration LoRA.

Copy `deepfake/experimental/wan_inputs.py` into the local ComfyUI `custom_nodes/` directory and restart that server. In the dedicated runtime, add this package to `PYTHONPATH`. Raw controls are an NPZ with RGB `uint8` arrays: `reference` HWC, `background` NHWC, `pose` NHWC, `face` NHWC; `mask` is finite float coverage NHW in [0,1]. All video batches must have matching frame counts, equal to 4n+1. Produce actual pose, face-crop and tracked person-mask controls with DWPose/SAM2 or equivalent reviewed preprocessing; the loader does not invent them. The local benchmark selects the foreground actor and explicitly excludes microphones and the rear guest using SAM2 prompts. Prompt coordinates are clip-specific, not automatic object detection.

```sh
python -m deepfake.experimental.wan_inputs raw-controls.npz prepared-controls.npz
python -m deepfake.experimental.wan_replacement prepared-controls.npz --output-dir run-records
```

Preparation preserves the whole reference portrait with letterboxing, expands/blockifies the person mask, and blacks out that region in the original background. The node hashes changed input files to invalidate cached controls. The adapter submits only to a local server and writes the graph, prompt ID and completion history. ComfyUI frame outputs are private experiment intermediates; apply disclosure and the production final-encode/signing path before sharing a video. There is no automatic model download, public upload, realtime body preset or signed export in this graph-submission helper.
